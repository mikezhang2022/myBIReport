# ProductionProcessBi 单服务器部署说明

浏览器只需输入服务器的网址即可访问，无需在本机复制或运行前端。API、前台报表页面和后台管理页面都由同一个 ASP.NET Core 进程托管。

> 以下示例假设服务器 IP 是 `10.27.230.47`，监听端口 `5095`。如果你的 IP 或端口不同，请替换所有相关地址。

## 一、在服务器启动（唯一需要的服务）

进入 `ProductionProcessBi` 项目目录，启动 API（同时托管两个前端）：

```powershell
cd ProductionProcessBi
dotnet run --urls http://0.0.0.0:5095
```

启动成功后，浏览器直接访问：

| 页面 | 地址 |
| --- | --- |
| 前台报表页面 | `http://10.27.230.47:5095/` |
| 后台管理页面 | `http://10.27.230.47:5095/admin/` |
| API 状态/信息 | `http://10.27.230.47:5095/api` |

- 前台与后台的 API 请求都是相对于当前网址的同源路径（例如 `/api/auth/login`），不再依赖 `5173` 端口、Python 代理或单独配置的后端地址。
- 首次打开后台或前台会进入初始化向导：创建系统管理员账号（密码至少 2 位），之后可在后台添加其他账号并分配报表权限。

## 二、发布到生产（可选）

```powershell
cd ProductionProcessBi
dotnet publish -c Release -o ./publish
```

发布后的 `publish` 目录已包含 `Frontend` 和 `Admin` 的静态资源，直接用以下命令运行即可：

```powershell
cd publish
dotnet ProductionProcessBi.dll --urls http://0.0.0.0:5095
```

## 三、防火墙端口

服务器只需允许局域网访问一个 TCP 端口：

| 端口 | 用途 |
| --- | --- |
| 5095 | ProductionProcessBi（API + 前台 + 后台） |

不再需要为前端单独开放 `5173`、`5174` 等端口。

## 四、账号与报表权限

- `system-admin`：系统管理员，可以管理用户、数据源和全部报表。
- `report-admin`：报表管理员，可以管理和查看全部报表。
- `report-user`：普通报表用户，只能看到后台分配给自己的已发布报表。

如果普通用户登录后没有显示报表，请在后台的“用户与权限”页面中给该用户勾选对应报表，并确认报表处于已发布状态。

## 五、安全说明

- 数据源的连接字符串（含密码）只保存在服务器 `data/` 目录中，不会通过 `/api/data-sources` 返回给浏览器；管理界面仅显示脱敏后的连接信息。
- 用户密码以 PBKDF2 哈希存储，前端与后端均要求密码至少 2 位。
- 后台与数据源管理要求系统管理员权限，普通账号无法进入。

## 六、常见问题

### 无法连接

在前台或后台所在浏览器中打开 `http://10.27.230.47:5095/api`，应返回包含 `service` 与 `status` 的 JSON。如果打不开，请检查：

1. API 是否使用 `http://0.0.0.0:5095` 启动。
2. 服务器 IP 是否仍为 `10.27.230.47`。
3. 服务器防火墙是否允许端口 `5095`。

### 关闭服务

在运行 `dotnet run` 的 PowerShell 窗口中按 `Ctrl + C` 即可停止。
