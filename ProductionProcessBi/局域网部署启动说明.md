# ProductionProcessBi 单服务器部署说明

浏览器只需输入服务器的网址即可访问，无需在本机复制或运行前端。API、前台报表页面和后台管理页面都由同一个 ASP.NET Core 进程托管。

> 以下示例假设服务器 IP 是 `10.27.230.47`，监听端口 `5095`。如果你的 IP 或端口不同，请替换所有相关地址。

## 两种部署方式

- **方式一（默认推荐）：单服务器直接部署** —— 由 ASP.NET Core 一个进程同时托管 API、前台和后台。见下文第一节至第六节。
- **方式二（可选）：Node 反向代理局域网部署** —— 由 ASP.NET Core 在回环地址 `5095` 提供 API，再用本仓库自带的 `node-server.js`（零依赖，无需 `npm install`）在局域网端口 `5173` 提供前台/后台并转发 `/api`。适合希望把对外端口与 .NET 端口分离、或复用既有 Node 环境的场景。**Node 不替代 .NET 后端**，它只是静态资源和 API 转发的入口。见第七节。

两种方式对客户端浏览器的访问效果一致；测试/使用电脑只需要一个浏览器，无需在本机安装或运行任何服务端程序。

## 一、在服务器启动（唯一需要的服务）

进入 `ProductionProcessBi` 项目目录，启动 API（同时托管两个前端）：

```powershell
cd ProductionProcessBi
dotnet run --urls http://0.0.0.0:5095
```

启动成功后，浏览器直接访问：

| 页面 | 地址 |
| --- | --- |
| 前台报表页面 | `http://10.27.230.47:5095/` |
| 后台管理页面 | `http://10.27.230.47:5095/admin/` |
| API 状态/信息 | `http://10.27.230.47:5095/api` |

- 前台与后台的 API 请求都是相对于当前网址的同源路径（例如 `/api/auth/login`），不再依赖 `5173` 端口、Python 代理或单独配置的后端地址。
- 首次打开后台或前台会进入初始化向导：创建系统管理员账号（密码至少 2 位），之后可在后台添加其他账号并分配报表权限。

## 二、发布到生产（可选）

```powershell
cd ProductionProcessBi
dotnet publish -c Release -o ./publish
```

发布后的 `publish` 目录已包含 `Frontend` 和 `Admin` 的静态资源，直接用以下命令运行即可：

```powershell
cd publish
dotnet ProductionProcessBi.dll --urls http://0.0.0.0:5095
```

## 三、防火墙端口

服务器只需允许局域网访问一个 TCP 端口：

| 端口 | 用途 |
| --- | --- |
| 5095 | ProductionProcessBi（API + 前台 + 后台） |

不再需要为前端单独开放 `5173`、`5174` 等端口。

## 四、账号与报表权限

- `system-admin`：系统管理员，可以管理用户、数据源和全部报表。
- `report-admin`：报表管理员，可以管理和查看全部报表。
- `report-user`：普通报表用户，只能看到后台分配给自己的已发布报表。

如果普通用户登录后没有显示报表，请在后台的“用户与权限”页面中给该用户勾选对应报表，并确认报表处于已发布状态。

## 五、安全说明

- 数据源的连接字符串（含密码）只保存在服务器 `data/` 目录中，不会通过 `/api/data-sources` 返回给浏览器；管理界面仅显示脱敏后的连接信息。
- 用户密码以 PBKDF2 哈希存储，前端与后端均要求密码至少 2 位。
- 后台与数据源管理要求系统管理员权限，普通账号无法进入。

## 六、常见问题

### 无法连接

在前台或后台所在浏览器中打开 `http://10.27.230.47:5095/api`，应返回包含 `service` 与 `status` 的 JSON。如果打不开，请检查：

1. API 是否使用 `http://0.0.0.0:5095` 启动。
2. 服务器 IP 是否仍为 `10.27.230.47`。
3. 服务器防火墙是否允许端口 `5095`。

### 关闭服务

在运行 `dotnet run` 的 PowerShell 窗口中按 `Ctrl + C` 即可停止。

## 七、备选：使用 Node 反向代理的局域网部署（可选）

> 此方式需要服务器上安装 Node.js（18 或更高版本）。它**不替代** ASP.NET Core 后端：`.NET` 进程仍然负责全部 API 与数据；Node 只负责把浏览器请求转发到回环地址上的 `.NET` 进程。

### 1. 在服务器上启动两个终端（顺序：先 .NET，后 Node）

**终端 A —— 启动 .NET API（只监听本机回环，不对外暴露）：**

```powershell
cd ProductionProcessBi
dotnet run --urls http://127.0.0.1:5095
```

> 这里用 `127.0.0.1` 回环地址，`.NET` 只接受来自本机的请求；对外的 `5173` 由 Node 统一承接。

**终端 B —— 启动 Node 转发（监听局域网地址与端口）：**

```powershell
cd ProductionProcessBi
node node-server.js
```

默认即监听 `0.0.0.0:5173`，并把 `/api` 转发到 `http://127.0.0.1:5095`。如需自定义，用环境变量覆盖：

```powershell
$env:HOST='0.0.0.0'; $env:PORT='5173'; $env:API_ORIGIN='http://127.0.0.1:5095'; node node-server.js
```

启动成功后终端 B 会打印前台、后台与上游 API 地址。

### 2. 客户端电脑（测试/使用电脑）只需浏览器

| 用途 | 地址（把 IP 换成服务器实际局域网 IP） |
| --- | --- |
| 前台报表页面 | `http://10.27.230.47:5173/` |
| 后台管理页面 | `http://10.27.230.47:5173/admin/` |
| API 状态/信息 | `http://10.27.230.47:5173/api`（由 Node 转发到 .NET） |

- 客户端浏览器中的所有 API 请求都是相对于 `5173` 的同源 `/api/...`，由 Node 原样转发到 `5095`，**登录 Cookie、状态码、响应头、请求体与权限校验都保持不变**，因此跨局域网的登录与按角色过滤的报表列表均可正常工作。
- 客户端电脑不需要安装 Node、.NET，也不需要复制前端文件，只要能访问服务器 `5173` 端口即可。

### 3. 防火墙端口

| 端口 | 暴露对象 | 用途 |
| --- | --- | --- |
| 5173 | 局域网客户端 | 前台/后台入口（由 Node 监听） |
| 5095 | 仅本机（回环） | .NET API，对外不需要开放 |

只需在服务器防火墙允许 **5173** 端口对局域网入站；`5095` 保持在 `127.0.0.1` 回环，无需对外放行。

### 4. 发布到生产（可选）

`dotnet publish` 已经会把 `node-server.js` 一并复制到发布目录的根（位于 `Frontend`/`Admin` 静态根之外，不会被当作静态资源暴露）。发布后这样运行：

```powershell
# 终端 A：.NET API（回环）
cd publish
dotnet ProductionProcessBi.dll --urls http://127.0.0.1:5095

# 终端 B：Node 转发（局域网）
cd publish
node node-server.js
```

### 5. 安全与注意事项

- Node 仅转发已由 `.NET` 鉴权的 `/api` 请求，**不会削弱任何 API 授权**；普通用户仍然只能看到后台分配给自己的报表。
- Node 静态服务只暴露 `Frontend` 与 `Admin` 中的浏览器资源，明确屏蔽了 `node-server.js`、Python 脚本（`.py`）、PowerShell 脚本（`.ps1`）、`README` 以及 `data/` 目录，不支持路径穿越。
- 如果 `5173` 端口被占用，用 `PORT` 环境变量换成其它端口，并相应更新防火墙与客户端访问地址。

### 6. 关闭服务

分别在终端 A、终端 B 按 `Ctrl + C` 停止。若只关掉 Node，浏览器将无法通过 `5173` 访问（API 仍在 `5095` 本机运行）。
